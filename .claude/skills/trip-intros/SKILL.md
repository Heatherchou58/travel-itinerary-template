# 替行程補景點介紹

`stop` 區塊的 `intro` 是**背景知識**——這地方是什麼、為什麼值得看、到了要看什麼。網站上收合成「看介紹」，點了才展開。

它跟 `notes` 是兩種東西，不要混：

| 欄位 | 放什麼 | 誰來填 |
|---|---|---|
| `notes` | 操作資訊：交通時間、停留多久、開放時間、要先預約 | 使用者自己查的，比較可靠，**不要動** |
| `intro` | 背景知識：歷史、看點、特色 | 這個流程產生 |

---

## 流程

### 1. 讀出行程，列出候選

用大括號配對（不是正則）從 `index.html` 取出 `TRIP_DATA`，列出所有 `type === "stop"` 的項目，標出 `kind` 與現有的 `intro`。

**要寫的**：`sight`（景點）、`meal`（美食）、`shop`（購物）。

**跳過**：住宿（`lodging`）、以及雖然是 `stop` 但不是景點的流程性項目——取車、還車、辦理登機、寄放行李、退房、前往機場、抵達出境。

名稱籠統的餐飲（「博多晚餐」「午餐」）如果有指定**區域或菜色**，寫當地特色為什麼值得吃；完全沒有線索的就跳過。

### 2. 逐項查證，不憑記憶寫

**這一步不能省。** 旅遊資訊寫錯比不寫更糟。

特別要查的是會變的東西：

- 這個地方**現在還在不在、能不能進去**（火山規制、重建、整修、歇業）
- 季節性現象的**實際發生時間**，再對照行程日期
- 名店的創業年份、特色這類容易記錯的細節

實際抓到過的例子：

| 查證結果 | 影響 |
|---|---|
| 宮地嶽神社「光之道」一年只在 2 月與 10 月的日落前後數日出現 | 行程排在 11 月上午，根本看不到，`notes` 原本寫「光之道拍照景點」會害人空等 |
| 旦過市場 2022 年兩場大火後仍在重建，新設施 2027 年春季才開幕 | 不能描述成完好的百年市場 |
| 阿蘇中岳火口受噴火警戒等級管制，隨時可能封閉 | 要提醒出發前查官方規制情報 |
| 太宰府天滿宮的臨時「仮殿」2026 年 5 月已結束 | 寫「可以看到仮殿」就錯了 |

景點多的時候可以用 subagent 分組平行查，但**每一項都要有查證依據**，不能因為趕而略過。

### 3. 撰寫

- 每篇 2～4 句，約 100～250 字
- 只寫**穩定的背景**。**不要寫價格、營業時間、公休日**——那些會過時，而且 `notes` 裡已經有使用者自己查的版本
- 時效性的事實若非寫不可，改寫成不會過期的形式。例如不要寫「目前 2 級警戒」，要寫「出發前務必查官方規制情報」
- 沒把握的具體數字（幾座燈籠、幾公尺、哪一年）要嘛查到可靠來源，要嘛不要寫
- 段落之間用 `\n`，網站會自動分段

### 4. 注入

修改 `fukuoka-2026/index.html` 之類的已產出網站時，**先確認重新序列化後與原檔完全一致**：

```js
if (JSON.stringify(T, null, 2) !== raw) {
  console.error("格式不一致，停止——注入會順便改寫整段 TRIP_DATA");
  process.exit(1);
}
```

不檢查的話 diff 會變成整片重寫，看不出到底改了什麼。

用 `${day.nav}|${block.title}` 當鍵比對，因為標題會重複（「博多晚餐」在 D1 和 D5 都有）。對不上的鍵要報錯，不要安靜跳過。

注入後確認 diff 只有新增的 `intro`，以及前一個屬性補上的逗號。

### 5. 重新產生網站後要保留

使用者用 builder 重新產生網站時，`TRIP_DATA` 會被整個換掉，**既有的 intro 會消失**，除非它們填在 Excel 的「介紹」欄裡。

所以遇到「行程更新了，介紹不見了」時：

1. 從 git 歷史取回舊版的 intro（`git show <舊 commit>:<檔案>`）
2. 用標題比對，把還存在的景點的 intro 搬回來
3. 只針對**新增的**景點做查證與撰寫

也可以把 intro 整理成「標題 → 介紹」的對照表給使用者貼進 Excel 的 K 欄，之後重新產生就不會再掉。

### 6. 驗證

```bash
python tests/offline_test.py
```

然後在瀏覽器實際看一眼：介紹有沒有渲染、是不是預設收合、換行有沒有分段。

**同步改 `builder/assets/site-template.html`**——如果這次動到的是顯示邏輯而不只是資料。詳見 `CLAUDE.md`。

## Excel 這一側

「行程」工作表的 **K 欄「介紹」**（在「說明／備註」右邊）。同一格內換行，網站上就會分段。

只有景點、餐飲、購物會顯示。填在其他類型上，`parse.js` 會發出警告而不是安靜丟掉。
